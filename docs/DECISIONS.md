# Decisions log

Choices made while implementing `crm-platform-build-spec.md`, including every `[DECIDE]` item and any deviation from the spec. Newest at the bottom.

## Phase 0

1. **Next.js 16 rather than 15.** Spec says "15+". Next 16 renames `middleware.ts` to `proxy.ts` (Node runtime by default); the tenant rewrite lives in `src/proxy.ts`.
2. **Prisma pinned to 7.10.0.** The npm `latest` tag pointed at an 8.0 release candidate; 7.x is the current stable. Prisma 7 requires `prisma.config.ts`, the `prisma-client` generator with an explicit `output` (`src/generated/prisma`, git-ignored, regenerated by `postinstall`), and a driver adapter (`@prisma/adapter-pg`).
3. **Tenant isolation via a Prisma client extension** (spec §4 `[DECIDE]`). Every top-level operation on every tenant-scoped model gets `AND: [{ tenantId }]` appended; creates get `tenantId` forced. AND semantics were chosen over overriding the caller's filter so a query that names another tenant matches nothing rather than being silently redirected. The scoped-model list is explicit (`TENANT_SCOPED_MODELS`) because Prisma 7's generated client exposes no runtime DMMF; a unit test parses the schema and fails if the list drifts.
4. **`tenantId` on every child table too** (OrderItem, CartItem, ProductImage, ProductVariant, Address, OrderStatusEvent, Payment), not just aggregates. Slightly denormalised, but it lets the extension scope every model uniformly and avoids the "child table reachable without a tenant filter" hole.
5. **Customer accounts are separate per tenant** (spec §5 `[DECIDE]`). `UserRole.CUSTOMER` was added to the enum; a `User` always belongs to exactly one tenant except super admins. Same email in two stores = two accounts.
6. **Product variants are in the v1 schema** (spec §6, confirmed by the owner). `Product.hasVariants` flags whether stock is tracked on the product or on its `ProductVariant` rows; both carry SKUs unique per tenant.
7. **Money as integer minor units; tax in basis points; flat shipping per tenant** (confirmed by the owner). `Tenant.shippingFlatRate` and `Tenant.taxRateBps` drive checkout totals via pure helpers in `src/lib/money`. Currency, country and locale are per-tenant settings with USD/US/en-US as seed defaults until the first client's region is chosen.
8. **Order status transitions** (spec §6, flagged deviation): the enum is used exactly as specified. Transition rules allow `DELIVERED → REFUNDED` so post-delivery returns can be recorded; everything else follows the spec (no backwards moves, CANCELLED/REFUNDED terminal, SHIPPED cannot be cancelled, only refunded).
9. **Per-tenant sequential order numbers.** `Order.orderNumber` is unique per tenant and assigned from `Tenant.orderSequence` with an atomic increment, giving customers a short ID for guest tracking (spec §7.5).
10. **Auth.js: JWT sessions, host-only cookies, DB re-verification.** Credentials provider requires JWT strategy. Cookies carry no `Domain` attribute, so sessions are per subdomain. Guards re-read the user row on every request rather than trusting token claims (spec §5/§9 "re-checked per request"). Passwords use `bcryptjs` cost 12 — Auth.js itself does not hash. Login rate limiting is inside `authorize` so the built-in callback endpoint is covered too; the v1 store is in-memory (per instance), with an interface ready for Upstash/Redis.
11. **Route layout.** `app/(root)` serves the apex (landing + `/platform` super-admin); `app/[tenant]` serves subdomains via proxy rewrite, with `(storefront)` and `admin` beneath it. Store admin therefore lives at `<slug>.<root>/admin`, which keeps its cookies isolated from other tenants. Login pages sit in `(auth)` route groups outside the guarded `(dashboard)` layouts to avoid redirect loops.
12. **Hand-written SQL in the initial migration.** A partial unique index on `User(email) WHERE tenantId IS NULL` (Prisma can't express it; Postgres treats NULLs as distinct in the composite unique) and CHECK constraints on money/quantity columns. Verified that `prisma migrate dev` reports no drift.
13. **`.env.test` is committed.** It holds only the local test-database URL and a dummy secret, and CI relies on it. All other `.env*` files are ignored.
14. **Deferred to later phases / fast-follow:** CSV bulk product upload (spec §7.1 `[DECIDE]` → fast-follow), OAuth providers, custom domains (v2 extension point noted in `resolve.ts`), Row Level Security. Third-party providers (Stripe, Resend, Vercel Blob, hosted Postgres) are reserved as env vars and chosen when the product goes live.
15. **Local database is Docker Postgres 17** (owner's choice); `docker-compose.yml` creates both `zy_commerce` and `zy_commerce_test`.

## Going live (2026-09-04)

16. **Hosted database is Supabase; app on Vercel** (owner's choice). Runtime uses the pooled connection, the Prisma CLI uses the direct/session connection. `src/lib/db/connection.ts` resolves `DATABASE_URL`/`DIRECT_URL` and also the `POSTGRES_*` names the Vercel ↔ Supabase integration injects, so no manual mapping is needed.
17. **TLS policy for hosted Postgres.** node-postgres treats `sslmode=require` as full verification (and warns); Supabase URLs mean the libpq sense. `buildPoolSettings` maps require/prefer/no-verify → encrypted without verification, `verify-full` → verified, and encrypts by default for any non-local host.
18. **Migrations and seed run inside the Vercel production build** (`scripts/vercel-build.sh`), never for previews. The seed refuses to invent passwords on Vercel/production: accounts are created only when `SEED_*_PASSWORD` is set, so credentials never appear in build logs.
19. **Tenant host aliases** (`TENANT_HOST_ALIASES`). `*.vercel.app` cannot nest subdomains, so the demo store is served from its own vercel.app alias. The same mechanism is the v1 form of per-tenant custom domains; v2 moves it to a `Tenant.customDomain` column.
20. **Vercel project `zy-commerce` (team kzy02), functions in `sin1` (Singapore), Supabase in `ap-southeast-1`.** The owner is in the UTC+8 region and the first demo tenant is configured for MYR/MY, so the app and database sit next to each other in Singapore. The demo tenant is served from the alias `zy-commerce-demo.vercel.app` via `TENANT_HOST_ALIASES`; the platform root is `zy-commerce.vercel.app`.
21. **Database URLs are stripped of `sslmode`/`ssl*` params before reaching node-postgres.** pg merges the parsed URL over the explicit config, so Supabase's `sslmode=require` silently re-enabled certificate verification and the first production seed failed on Supabase's self-signed chain. `buildPoolSettings()` now removes those params textually and is the single source of truth for TLS. The Prisma CLI (migrate) handles TLS itself and was unaffected.
22. **Production is live** (2026-09-06): https://zy-commerce.vercel.app and https://zy-commerce-demo.vercel.app. Super-admin and demo-admin passwords live only in the Vercel project's environment variables (`SEED_*_PASSWORD`); a self-service password change is Phase 5 work.
